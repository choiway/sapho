# Sapho reading UX — product pivot

**Status:** historical design proposal. The current UX opens the floating chat directly with `:Sapho` or the optional mapping; Telescope is only used for `:SaphoLocations`. See `README.md` for current behavior. This plan replaced the product direction in `PLAN.md` and the edit workflow in M5/M5a; those documents also describe historical implementations. Keep writing in the coding harness (pi). Sapho helps a human *understand* code in Neovim. Do not start a new repository: reuse the provider, streaming, session, and bounded Neovim read tools already here.

## The loop

1. From a normal source buffer, a user-configured leader mapping (examples: `<leader>sa` normal/visual) opens a Telescope **action picker**. `:Sapho` is the command equivalent. Telescope is for choosing a task or navigating findings, not for writing a multi-line question.
2. The first/default action is **Ask about this buffer**. Other initial actions: **Explain selection** (when selected), **Explain diagnostic at cursor**, **Trace definition**, **Find references**, **Continue conversation**. Actions prefill an editable prompt; none immediately sends a request. Missing diagnostics/LSP must produce a useful message, not a blank or blocking picker.
3. Choosing an action opens a small, multiline prompt adjacent to the source. The transcript/answer can expand beside it but must not replace the source window. Put the attached file path and selected range in a visible context header. For a visual selection, prepopulate the prompt with a question starter and a readable, quoted selection (bounded with a truncation notice); focus the question so the user can edit it before submission. Insert `<CR>` is a newline; `<C-s>` submits; normal `<CR>` submits; `<C-c>` cancels an active request. The prompt must never submit automatically on picker choice.
4. Stream the answer beside the code. Keep source windows/cursor/scroll position unchanged while the model works. Answer text is primary; a compact activity trail exposes tool names and human-readable targets (e.g. `Reading foo.lua:20–60`, `Checking definitions`) but not raw arguments, secret content, or reasoning ciphertext. Show errors and cancellation, preserve unsent drafts, and allow a follow-up without reopening Telescope.
5. Locations found through tools or named in a structured result become selectable references (Telescope picker or location list, with filename, line, preview). **Only user activation jumps**; the LLM cannot move the editor, write buffers, create quickfix entries, run Ex commands, or alter layout. Returning a location is a read; publishing or navigating is a user action.

## Context contract

- Capture `bufnr`, path (including an unnamed buffer label), window, cursor byte position, filetype, `changedtick`, and any visual selection **before** opening Telescope (picker/UI focus changes mode, marks and current buffer). Handle characterwise, linewise and blockwise selections, reversed endpoints, multibyte text and empty selection; bound bytes/lines and show truncation. Don't rely on `'<`/`'>` marks from an older visual selection for a normal-mode invocation. The selection in the prompt is editable user text, not a hidden instruction.
- At submit time attach the source buffer identity and current `changedtick`; the model may request fresh unsaved text through `buffer_read`. If the original buffer is wiped or ceases to be a normal buffer, explain that context is unavailable rather than silently switching files. A changed buffer is read fresh; never claim the originally quoted selection reflects later edits. The selection remains pinned for this question, while `editor_context` may report the **current** source cursor/selection explicitly marked as live. No automatic context switching just because focus moves during streaming.
- Default scope is the invoking buffer plus explicit selection. Other repository reads are available only when the user asks to follow a dependency/caller, through bounded, cwd-confined tools; prefer loaded unsaved buffers over disk. Visibly label any expansion beyond the source file. No implicit repository-wide scan for a simple buffer question.
- Start a conversation associated with its source buffer; re-entry from that buffer resumes it. Starting from another buffer uses a separate conversation. Expose **New conversation** and make prior context/selected excerpt visible so a follow-up is not accidentally grounded in the wrong file. On source-buffer wipe, retire its session and cancel outstanding work. No disk persistence in the first pass.

## Model tools and permissions

Advertise an ordered, stable **allowlist of read-only Neovim tools**. Reuse `buffer_read`, `lsp_diagnostics`, `lsp_definition`, `editor_context`, and bounded `repo_read` where needed. Add `lsp_references` and `lsp_document_symbols` (and optionally `ts_enclosing_scope` after the LSP path works). Return bounded structured results with path/range, encoding, source buffer identity and clear errors; respect LSP timeouts/cancellation and unsaved text. If a server is absent, the model should say so and answer from available buffer text instead of inventing a definition. Restrict repository reads to source files within cwd and never expose credentials/special buffers.

Remove `buffer_edit` from **both** advertised schemas and dispatch; remove the auto-apply/review hooks from the agent and entry UI. Update the byte-stable provider instructions to be reading-only. Do not expose `nvim_command`, `nvim_exec_lua`, shell, filesystem writes, LSP rename, or navigation-as-a-tool. Any future write feature requires a separate opt-in design; it is not an action in this picker. A tool result is data for an answer, not authority to change the editor. Display activity before each call and a bounded error/success indicator after it; do not let model-supplied text become an Ex command or a keymap.

## Implementation sequence

1. **Remove writing capability.** Change tool registry, agent, provider instructions, and tests first so no UI path can accidentally apply edits. Retire edit config/commands and review/diff modules only after the read-only path is covered. Preserve provider/auth/SSE/session behavior and existing cancellation semantics.
2. **Context capture and picker.** Add a dedicated context module with tested visual-mode extraction and source validation. Add a Telescope adapter with action availability and a clear installation error if Telescope is missing. Choose an opt-in mapping via `setup({ keymap = '<leader>sa' })`; `:Sapho` works without a mapping. No forced global mapping and no takeover of a user's existing leader key.
3. **Prompt/answer layout.** Reuse the streaming transcript and input buffer, but make opening contextual and prompt-first. Focus the input; keep source in view. Show the selected excerpt and provenance in the prompt/context header; no invisible prompt augmentation that the user cannot inspect. Handle reopen, cancellation, multiple source buffers and cleanup without cross-session leakage.
4. **Semantic navigation.** Add bounded references/symbol tools and human-activated location picker. Report when results come from LSP vs unsaved buffer/disk. Keep navigation separate from model tool execution.
5. **Polish using real reading tasks.** Try explaining a selected function, understanding a diagnostic, tracing a call across files, and answering a follow-up after editing unsaved text. Prefer these flows over adding more agent autonomy.

## Acceptance checks (offline unless noted)

- Normal invocation shows Ask about this buffer first; visual invocation opens an editable prompt with exactly the intended selection (including reversed, linewise and blockwise cases), file/range and truncation indicator; no request before submit.
- The provider sees read-only schemas/instructions; a forged `buffer_edit` call returns an unknown-tool error, changes no buffer and is paired so the conversation can recover. Existing streaming, cancellation and session tests still pass.
- A buffer changed while the UI is open is read as current unsaved content by `buffer_read`; a wiped source cannot redirect a call to another buffer. Two source buffers never share conversation history by accident.
- A tool call cannot change cursor, windows, buffer contents, quickfix or disk. Selecting a returned location jumps correctly; merely receiving it does not. LSP missing, timeout and cancellation all finish cleanly.
- Telescope absence is explained; `:Sapho` remains usable or reports a specific dependency error, never a stack trace. Document the mapping and dependency in installation guidance when implemented.

## Decision to validate with hands-on use

The proposed default is a picker **before** the prompt even for an ordinary question, because that is the requested entry point. If this adds friction, retain the picker on `:Sapho`/the leader mapping but offer a second direct `ask()` API; do not make the user traverse two pickers or auto-submit a canned question.
