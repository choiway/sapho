# M4 — Read-only tools

**Goal:** Ask about an open source buffer and let Codex inspect its current unsaved contents, published diagnostics and LSP definition, then answer. No edits, filesystem reads, shell or permission prompts. Automated tests are offline.

## Design

- `tools/init.lua` exports an **ordered, stable** array of three Codex function schemas (`buffer_read`, `lsp_diagnostics`, `lsp_definition`) and `new(deps?):run(call, context, cb) -> cancel`. JSON schemas use `strict=true`, nullable required optional fields, `additionalProperties=false`; empty object properties use `vim.empty_dict()`. Results are bounded JSON strings; invalid JSON, unknown names, invalid buffer/ranges, LSP errors and timeouts return a tool error result (never execute arbitrary code). `call_id` is required to continue a turn. No raw tool arguments/results in the transcript.
- Source context is the non-Sapho buffer/window from which `:Sapho` was opened (updated when invoked from another source window). Buffer selection accepts only a currently **loaded normal buffer** with an exact path (or the captured source by default). Reject `auth.json`, Sapho buffers and non-loaded buffers. `buffer_read` uses `nvim_buf_get_lines` (includes unsaved edits), 1-based inclusive lines, max 200 lines/32 KiB. Diagnostics use `vim.diagnostic.get`, sorted/bounded. Definition uses `vim.lsp.buf_request_all` on attached clients, converts the requested byte column separately for each client's position encoding, cancels on timeout (5 s) or turn cancellation, sorts/deduplicates/bounds locations. No client yields a readable error, not a hang.
- `provider.start(input, events, done, deps?)` accepts `deps.tools` (ordered schema array); absent tools retains M2/M3 empty `[]`. Retry uses one frozen request JSON (including schemas). `instructions` remains byte-stable, `store=false`, `reasoning.encrypted_content` still requested. No credentials in argv.
- `agent.start(session, prompt, context, events, done, deps?) -> {cancel}` drives sequential Responses calls. Stage authoritative `response.output_item.done` items (including encrypted reasoning) and tool outputs locally. Dispatch every function call exactly once, in output order; send all results in the **same next request**. After a response with no calls, atomically commit the turn to `session.lua`, preserving request input order. On cancellation, incomplete/HTTP error, missing call_id or iteration cap, commit **nothing**. Accumulate usage across all response requests; limit to 6 requests and 8 calls per response, no unbounded loop. Cancellation terminates active provider/LSP request and suppresses late callbacks. Tools run only after a *completed* response; no calls from an incomplete one.
- UI uses the agent rather than provider directly. Only renders text/reasoning deltas and compact `[tool: name]` status; no raw arguments/contents/ciphertext. Buffer-local `<C-c>` and close cancellation remain. A final status replaces the M3 “tool not available” notice.

## Verification

- `tools_spec.lua`: stable schemas and JSON object encoding; loaded/unsaved buffer range, bounds and auth/scratch restrictions; diagnostics sorting; definition with fake clients (UTF-16 vs UTF-8), no clients, timeout, cancellation and late callbacks. No real LSP/network.
- `agent_spec.lua`: fake provider/tools, multiple and unknown calls, ordered authoritative history including encrypted reasoning, all call outputs before next request, aggregation, failed/cancelled turn rollback, iteration/call caps, one callback and late-event suppression.
- `provider_spec.lua`: injected schemas appear in body with stable order and on retries; default remains `tools=[]`.
- `init_spec.lua`: fake agent verifies source context, readable tool status, cancel/close and follow-up history. `make test` requires no login. A single live ChatGPT-plan Neovim request successfully called `buffer_read` on an unsaved source buffer, continued and answered; no tokens or streams were captured. No language server is installed in this environment, so actual attached-LSP acceptance remains a manual check; diagnostics/definition are exercised offline with injected clients.

**Out of scope:** buffer edits, executing shell, LSP rename, tool approval, arbitrary file loading, persistent sessions, parallel tool execution, and retrying failed tools automatically.
