# M5 — Interactive, reviewable edits

**Goal:** refactor through small, steerable checkpoints rather than a single large patch. While Sapho is paused on a proposed edit, the user can browse callers/definitions in ordinary Neovim buffers, compare the proposed change, and tell the agent what to do next. No shell, disk writes, Git commits, or approval system in M5.

**Done when:** ask for a refactor involving a function and its caller; inspect both during the turn; accept/reject/revise the first function-sized proposal; steer the caller change based on what was observed; finish with only reviewed changes. A stale proposal cannot overwrite a user edit. In the absence of intervening user writes/undos, one `u` per touched buffer reverts the agent's edits for that turn.

## 1. Interaction contract

- Default to **review before apply**. A `buffer_edit` call is a *proposal*, not an immediate mutation. One proposal per model response, targeting one loaded, named, modifiable, non-readonly source buffer inside the working directory. A proposal contains a bounded array of LSP `TextEdit`s (UTF-16/UTF-8 encoding made explicit), plus a short intent and optional symbol name. Limit edited lines/bytes and reject overlapping/out-of-bounds ranges. If a response includes multiple `buffer_edit` calls, return paired tool errors for all of them asking for one focused proposal; never silently apply the first. Other read-only calls in the response may finish, but the next provider request must wait for *all* tool results.
- At the edit tool boundary, pause the agent (no curl/LSP edit request in flight). Open a diff between the **unsaved source buffer** and a private scratch buffer with the proposal applied to that scratch buffer only. Show intent, target path, changed line ranges, and `Accept / Reject / Revise / Cancel` controls in Sapho's input/transcript; do not insert raw edit JSON into the transcript. Restore prior window/fold/diff options and clean preview buffers on every exit, including close/cancel/error. Do not steal focus after the initial review opens: normal Neovim `gd`, `<C-o>`, window navigation, diagnostics and quickfix continue to work.
- **Accept**: revalidate source buffer identity, loaded/modifiable/readonly status, `changedtick`, content snapshot and edit ranges; apply with `vim.lsp.util.apply_text_edits` on the real buffer; no `:write`. Return one `function_call_output` with applied status and affected range(s). Only then continue the model. **Reject**: no mutation; pair the `call_id` with a rejected result and optionally send reviewer feedback. **Revise**: reject this proposal with feedback and ask the model for a smaller/different one; never apply the rejected edit. Subsequent model requests must include the authoritative reasoning/output items, every call's paired result, and the review feedback, in order.
- Buffer-local review actions (and equivalent `:SaphoAccept`, `:SaphoReject`, `:SaphoRevise`, `:SaphoCancel`, `:SaphoPause` commands) are shown beside the proposal. While paused, normal input `<CR>` with nonempty text means **Revise with this feedback**; `Accept` is always explicit. Never auto-accept because a user submitted a prompt. Commands are session-scoped and no-ops with a clear status if there is no matching pending review.
- While streaming, submitting steering text must not pretend to interrupt an active Responses SSE request. Offer explicit `Pause after this response` and `Cancel now` actions. Queue steering until a *completed* response boundary; if the model is about to request an edit, stop at that edit preview. If the response ends **without** an edit call, show that the answer is complete and offer the queued steering as the next user turn (do not silently drop it). Cancellation of an in-flight request keeps no partial response; any earlier **accepted** edits remain visible and are reported clearly. While review is open, steering is immediate (no model request until the reviewer decides). Status distinguishes queued, paused, accepted, rejected, stale and cancelled.
- An edit proposal is stale on **any** `changedtick` change, even outside its range: close the preview, pair the call with a stale error and ask for a new proposal against the current buffer. Never automatically rebase or overwrite the user's work. If the user edits during a pause, they may continue the refactor, but Sapho starts a new undo group for that buffer rather than joining across user changes.

## 2. Editor context and exploration

- Remember the last *non-Sapho, non-preview* source window/buffer as the user navigates, not merely the buffer where `:Sapho` was first opened. Snapshot its buffer, cursor (1-based line/byte column), and optional explicit visual selection (bounded text) **when feedback is submitted**, not when the previous request began. Use extmarks for anchors displayed in the UI, but `changedtick` is authoritative for applying edits. Never read a buffer simply because its path was named in a model response; M4's loaded-buffer/auth restrictions apply.
- Add a small `editor_context` read-only tool for the current source buffer/cursor/explicit selection, and optionally `lsp_references` (same multi-client, timeout and location caps as `lsp_definition`) so the model can ask about callers. Append new schemas to the ordered M4 registry—do not reorder existing tools. Tool results are only sent to Codex, not dumped into the transcript. The user can also use existing Neovim LSP navigation and `buffer_read` while a preview is paused.
- Feedback such as “keep this signature; change its caller instead” becomes an explicit new user input item **after** the pending tool outputs, with the freshly captured editor context. Verify this continuation shape against the Codex backend before relying on it; on rejection, use a completed checkpoint and a new turn rather than silently dropping feedback. Update the fixed `instructions` once for M5 to ask for one focused tool proposal at a time; keep those instructions byte-stable thereafter and use `store=false`.

## 3. Turn/session/undo invariants

- M4's `agent.lua` currently stages an entire turn and commits only at the end. Extend it into explicit `streaming → collecting tools → paused_for_review → applying/continuing → done` states. The reviewer decision must be asynchronous; never block Neovim in a `vim.wait` or `vim.ui.select` loop. A pending review handle supports idempotent `accept`, `reject(feedback)`, `revise(feedback)`, `cancel`; only one decision wins. All tool calls receive exactly one result before the next request, including unknown/invalid calls.
- If **no edit was accepted**, keep the M4 atomic behavior: failed/cancelled turns do not enter history. On the first accepted edit, commit all *completed and fully paired* responses through that checkpoint (including encrypted reasoning and tool results). Later accepted edits add append-only checkpoints. If a later request fails/cancels, previous accepted edits and their recorded outputs remain; discard only the incomplete response. Never persist a function call without its result. Session usage accounts for completed responses once, even across failure/cancellation. A resume/follow-up must not resend a partial, unpaired response.
- Preserve one undo entry per buffer for a continuous agent edit turn by joining subsequent accepted applies only when both the expected `changedtick` and undo sequence still match the previous agent apply. Do not join across the user's writes, undo/redo, or unrelated plugin changes. Revalidate immediately before apply. The existing PLAN.md “one `u`” goal is **conditional** on no intervening writes: absorbing a user's edits into an agent undo group would be worse. Rejection/cancellation never calls `undo` implicitly; accepted edits are reversible in normal Neovim undo.
- No implicit disk writes, no Git staging/commit, no editing outside cwd (M6's permission tier handles that), no editing Sapho/auth/special buffers. Avoid storing full sensitive buffer text in notifications or error messages. The preview and any in-memory snapshots are disposed on cancellation/buffer wipe; persistence is M7.

## 4. Implementation sequence

1. Write offline tests for review state transitions and authoritative history/checkpoint semantics first. Extend `agent.lua` with a pausable continuation boundary and session checkpoint API; preserve M4 behavior when a turn only reads.
2. Implement `tools/buffer_edit.lua`: strict schema/argument validation (at most 8 text edits, 200 affected lines and 32 KiB replacement text per proposal), changedtick and range checks, bounded scratch-preview application and guarded real-buffer apply. Add read-only editor context and references as needed. Inject dependencies at the tool boundary; never replace Neovim globals globally in tests.
3. Add a review controller/UI (`ui/review.lua`) using existing transcript/input windows and a temporary diff split. Show the current proposal and pending steering; permit navigation without losing the review. Wire buffer-local actions, close/cancel cleanup and context capture.
4. Integrate provider continuations and status rendering; run `make test` without login. Manual acceptance with an attached LSP: refactor two interacting functions, navigate to a caller while paused, revise the second proposal, deliberately edit a source buffer to trigger stale detection, cancel after one accepted edit, and verify undo behavior and no credential/raw-edit leaks. Do not record live streams.

## 5. Offline test matrix

- Exact ordered schemas; valid/invalid edit JSON, encoding, overlapping/out-of-bounds ranges, line/byte caps, unloaded/special/auth/out-of-cwd/readonly targets, unsaved source content, scratch diff accuracy, no write to disk before or after accept.
- Accept/reject/revise, duplicate/late decisions, multiple edits in one response, read+edit call ordering, feedback snapshot after navigating to another function, and **no next provider request while paused**. At most one continuation after a decision, with every `call_id` answered and feedback ordered after tool outputs.
- Stale `changedtick`/undo/buffer wipe, cancellation and errors at each boundary, committed checkpoints after an accepted edit versus rollback before one, no partial calls in history, exact usage accounting, and no silent overwrites or post-close window recreation.
- Undo: one `u` per buffer reverts several agent applies when uninterrupted; intervening user write must remain independent. Multi-buffer changes need separate undo per buffer. No test needs Codex login or a real language server.

**Carry to M6:** approvals for outside-cwd writes and shell execution, plus optional optimistic auto-apply mode only after the review path is reliable. Keep interactive review as the default.
